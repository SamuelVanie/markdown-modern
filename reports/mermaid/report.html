markdown-modern / renderer audit / 28 October 2026

Mermaid rendering,
tested diagram by diagram.

Actual SVG output from the project's Emacs Lisp renderer, compared before and after fixes. 42 cases cover five built-in diagram families, seven unsupported families, and input handling.

42examples exercised
27rendered examples passing
25previously failing cases corrected
15expected source fallbacks

0 remaining failed fixture checks. A pass means the declared content, direction or marker assertions succeeded. It is not a claim of complete Mermaid compatibility.

Baseline: commit 6bd0385757d685d7a621b13864f0c2dfae2241ca. Emacs 31.1; fixed light palette for comparison. Each preview embeds the returned SVG as an isolated image; no Mermaid JavaScript or external assets are used.

Verification

Full suite: 291 passed, 0 failed, 3 skipped out of 294. The skipped tests require graphical list-marker measurements and are unrelated to Mermaid. Complete test log.

Browser geometry: 27 after SVGs measured; 0 with text outside the canvas, 0 failed to load. Measurements. Desktop and mobile report layout and filtering were checked separately.

Integration: tilde and longer backtick fences, source fallback, image-backend errors and theme-cache refresh have dedicated ERT tests. The modified renderer files also compile with warnings treated as errors.

What improved

Flowcharts now preserve chains, semicolons, explicit labels, supported shapes, undirected links and all four layout directions. They reuse the state renderer's routing to give cycles and multiline labels space. Class relationships now put the correct symbol on the correct endpoint. ER parsing accepts each cardinality, dashed links and isolated entities, places crow's feet next to their entities, and reserves room for attribute constraints. Leading comments and empty diagrams are handled consistently.

What still does not render

Subgraphs and advanced flowchart syntax, sequence activations, composite states, state notes and class multiplicity are source fallbacks in the tested cases. Pie, Gantt, mindmap, timeline, journey, Git graph and XY chart families have no built-in renderer.

The supported subset is intentionally limited. This audit does not establish complete support for styling, frontmatter, directives, actor silhouettes, class namespaces, custom shapes, HTML labels, or complex class/ER edge routing. Built-in HTML export still emits Mermaid fences as code, not diagrams. Browser previews validate SVG display; they do not substitute for a graphical Emacs/librsvg screenshot.

Evidence and reproduction

Machine-readable results: results.json · before.json · after.json. Fixtures and scripts live in the repository. The HTML is self-contained for sharing; these evidence files are optional companions.

emacs -Q --batch -L lisp -l scripts/mermaid-audit.el -- reports/mermaid/after.json
python3 scripts/mermaid-report.py
make test

Syntax checked against official Mermaid documentation: flowchart, sequence, state, class, ER. Tests target meaning and retained content, not pixel equality with upstream Mermaid.
